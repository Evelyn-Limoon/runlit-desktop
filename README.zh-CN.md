# RunLit

[English](README.md) · [使用手册](docs/user-guide.zh-CN.md) · [下载版本](https://github.com/Evelyn-Limoon/runlit-desktop/releases)

**看见 AI 工具已经做了什么，找到它留下的成果。**

RunLit 是一款本地桌面工具。它观察受支持 AI 工具的任务，把正在进行的工作、实质修改和成果文件放在同一个入口。平时它是一条轻量的浮动任务灯；需要查看时，点开任务就能看到状态和版本，并直接打开实际成果。

RunLit 只观察已有工作，不发送提示词、不发起 AI 任务，也不控制它所观察的工具。

> **公开预览版：** 支持 Windows x64 和 Linux x64。Windows 安装包目前未签名；暂不提供应用自动更新或云同步。

## 你可以用它做什么

- **集中找到不同工具的工作。** Codex 和 WorkBuddy AI 已内置接入；其他会生成本地文件的工具可以连接专用成果目录。
- **查看有依据的状态。** 来源提供足够证据时，RunLit 才显示进行中、已完成、已中断或状态未知。只找到软件安装路径，不等于发现了任务。
- **保留有意义的版本。** 一次交互确实改变成果时才形成一个版本，不把临时保存或每次工具调用都算作新版本。你也可以自行重命名版本。
- **打开真实成果。** 从任务详情打开文件、所在文件夹、项目目录或可信的结果链接。
- **排查漏识别。** 接入页面会显示扫描原因，并可保存诊断 JSON 报告。

## RunLit 怎样判断一个任务是否出现

| 接入方式 | 使用的证据 | 边界 |
| --- | --- | --- |
| Codex | 本地会话与工作目录、已完成的交互、生命周期记录、实际存在的成果文件 | 命令行写入文件时可能没有直接的文件变更记录。若只在命令运行时段找到文件，RunLit 会标为**可能的成果物**，不会把时间吻合当成归属证明。 |
| WorkBuddy AI | 本地会话、修改和成果记录 | 能否读取取决于本地数据格式和目录权限。 |
| 成果目录 | 连接指定目录后新建或修改的文件 | 只能说明目录里出现了成果，无法证明具体由哪个工具或提示词生成。 |

纯聊天、只检测到可执行程序，以及聊天里未经验证的文件或网址，都不会直接生成任务灯。证据尚不充分时，RunLit 会明确保留这种不确定性。

## 开始使用

1. 从 [GitHub Releases](https://github.com/Evelyn-Limoon/runlit-desktop/releases) 下载对应系统的安装包，并使用同一 Release 的校验文件核对下载结果。
2. 启动 RunLit，从浮球或通知区域菜单打开 **AI 工具接入**。
3. 检查 Codex 或 WorkBuddy 的连接状态。接入其他工具时，选择 **添加 AI 工具**，指定它保存成果的专用目录。
4. 在 AI 工具中实际新建或修改一个本地文件。内置接入通常约每五秒扫描一次，当前验收目标是 20 秒内发现。
5. 点击任务灯，查看版本并打开成果。

如果 Codex 显示已连接，但项目或成果没有出现，先查看 **AI 工具接入** 中的扫描统计，再选择 **保存诊断报告**。报告只包含接入状态和数量，不含本地路径、会话 ID、令牌或聊天正文；分享前仍请自行检查。

操作细节和故障排查见[中文使用手册](docs/user-guide.zh-CN.md)。

## 本地数据与隐私

RunLit 只监听 `127.0.0.1`。安装版的数据库和设置留在当前用户的应用数据目录。它保存导航任务所需的标识、状态、工作目录、时间、证据和成果引用，不保存 AI 聊天正文、浏览器 Cookie、密码或 AI 工具登录令牌。

本地 API 使用受信应用来源或安装专属令牌保护。RunLit 不要求账号，也没有分析埋点或后台上传任务数据。详情见[隐私政策](PRIVACY.md)和[安全政策](SECURITY.md)。

## 当前预览版的范围

- 支持 Windows x64 和 Linux x64；暂不支持 macOS 与 ARM64。
- Windows 预览版尚未签名，系统可能提示“未知发布者”。安装前请对照 Release 校验文件。
- 只有 Codex 和 WorkBuddy AI 提供内置任务接入。其他本地工具可在输出文件时使用成果目录监控。
- AI 工具的数据格式可能改变。接入状态与诊断报告用于区分“发现软件”和“真正检测到任务”。
- 暂无云同步和应用自动更新。

## 从源码运行

需要 Node.js 24+、npm、Rust，以及对应平台的 [Tauri 构建依赖](https://v2.tauri.app/start/prerequisites/)。

```powershell
npm ci
npm test
npm run build
npm run start:runlit
```

Linux 使用 `npm run start:runlit:linux`。安装包已自带 Node.js 运行环境，普通用户不需要上述构建工具。开发者可查看[适配器指南](docs/adapter-development.md)、[贡献指南](CONTRIBUTING.md)和[发布流程](docs/release-process.md)。
