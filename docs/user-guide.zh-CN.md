# RunLit 用户手册

> 状态：GitHub 公开发布准备稿
> 当前产品范围：Windows x64、Codex 与 WorkBuddy AI、本地优先

[English](user-guide.en.md) | [开发者适配器指南](adapter-development.md)

## 1. RunLit 是什么

RunLit 是一个常驻 Windows 桌面的 AI 任务观察与成果导航工具。它把不同 AI 工具中已经产生真实本地修改的任务整理成任务灯，并显示：

- 任务来自哪个 AI 工具；
- 当前是进行中、已完成、已中断还是状态未知；
- 每次产生实质修改的交互所对应的版本；
- 本次修改生成的文件、文件夹或可信结果链接。

RunLit 不负责发起或控制 AI 任务，也不会根据进程存在、普通聊天或长时间无响应猜测任务已经完成。没有足够证据的会话不会进入任务灯条。

## 2. 当前支持范围

| AI 工具 | 接入方式 | 用户需要做什么 | 当前状态 |
| --- | --- | --- | --- |
| Codex | Codex App Server 与本地生命周期记录 | 通常无需设置；RunLit 会自动发现 Codex | 已内置 |
| WorkBuddy AI | 本地会话、修改与成果物索引 | 通常自动发现；失败时可手动指定数据目录 | 已内置 |
| 其他会输出本地文件的 AI 工具 | 通用成果目录监控 | 在“AI 工具接入”中填写工具名称并选择专用成果目录 | 可手动接入，仅识别成果物 |
| 需要精确任务状态的其他工具 | 对应的专用 RunLit Adapter | 安装或开发对应 Adapter | 尚未内置 |

看到某个工具的 Logo 不等于该工具已经完成数据接入。是否真正可用，应以 **AI 工具接入** 页面显示的状态为准。

## 3. 安装前须知

当前公开目标平台是 Windows x64。安装版自带 RunLit 后台运行环境，普通用户不需要另外安装 Node.js、npm 或 Rust。

在使用 RunLit 前，至少应安装并能够正常运行一个受支持的 AI 工具：

- 使用 Codex 接入时，先安装 Codex Desktop 或 Codex CLI；
- 使用 WorkBuddy 接入时，先运行 WorkBuddy，使其创建本地数据目录。

RunLit 自身通过本地数据完成任务检测，不依赖互联网刷新；AI 工具是否需要联网取决于该工具本身。

### 关于开发预览版

0.1.0 开发安装包目前尚未代码签名。通过浏览器下载时，Windows 可能显示“未知发布者”或 SmartScreen 提示。正式 GitHub Release 必须明确标注其是否已签名，并同时发布安装包的 SHA-256 校验值。

## 4. 从 GitHub 安装

正式公开后，请从项目仓库的 **Releases** 页面下载安装包，不要从第三方下载站获取。

1. 打开最新的 RunLit Release。
2. 阅读版本说明、支持范围和已知问题。
3. 下载以下任一 Windows x64 安装包：
   - `Setup.exe`：适合普通用户；
   - `.msi`：适合需要 MSI 部署的环境。
4. 对照 Release 页面提供的 SHA-256 校验值。
5. 完成安装并从开始菜单启动 RunLit。

启动后，Windows 任务栏和通知区域会显示 RunLit 图标，桌面上会出现可以拖动的圆形浮球。

## 5. 连接 AI 工具

### 打开接入页面

使用以下任一种方式：

- 右键单击 RunLit 浮球，选择 **AI 工具接入…**；
- 右键单击 Windows 通知区域中的 RunLit 图标，选择 **AI 工具接入…**。

接入页面会分别显示每个 Adapter 的状态、发现路径、最近错误和重新检测按钮。

| 状态 | 含义 | 建议操作 |
| --- | --- | --- |
| 已连接 | Adapter 已找到工具或数据目录，正在自动观察 | 无需操作 |
| 正在连接 | RunLit 正在首次连接或扫描 | 等待几秒 |
| 未发现 | 没有找到程序或本地数据 | 检查安装位置，随后重新检测 |
| 连接异常 | 已找到来源，但读取或启动失败 | 查看页面中的错误信息并按故障排查处理 |
| 已关闭 | 该 Adapter 被启动配置关闭 | 重新启动并启用对应 Adapter |

### 连接 Codex

RunLit 按以下顺序自动寻找 Codex：

1. 高级用户设置的 `RUNLIT_CODEX_PATH`；
2. Windows `PATH` 中的 Codex；
3. 当前用户的 Codex Desktop 安装目录。

正常安装的用户通常不需要输入路径。若 Codex 显示 **未发现**：

1. 确认 Codex Desktop 或 Codex CLI 能独立启动；
2. 打开 **AI 工具接入…**；
3. 在 Codex 卡片上选择 **重新检测**；
4. 仍未找到时，参考“故障排查”中的 Codex 项目。

### 连接 WorkBuddy AI

RunLit 会先寻找当前用户目录中的 `.workbuddy-ai` 数据目录。自动发现失败时：

1. 打开 **AI 工具接入…**；
2. 找到 WorkBuddy AI 卡片；
3. 输入 WorkBuddy 数据目录，例如 `C:\Users\你的用户名\.workbuddy-ai`；
4. 选择 **保存并连接**；
5. 确认状态变为 **已连接**。

所选目录中应包含 `projects` 子目录。该设置保存在 RunLit 的用户数据中，不会写入项目源码。

## 6. 怎样让任务进入灯条

连接成功不代表所有聊天都会显示。一个任务进入灯条，需要同时具备可验证的工作对象、执行活动和成果物证据。

推荐测试流程：

1. 在 Codex 或 WorkBuddy 中打开一个本地项目或文件夹。
2. 发出会实质修改本地内容的要求，例如创建、编辑、生成或导出文件。
3. 等待 AI 工具完成文件操作。
4. RunLit 会自动扫描；通常数秒内更新，验收目标是不超过 20 秒。
5. 新任务会出现在浮球旁的任务灯条中。

以下情况通常不会进入灯条：

- 只进行问答，没有修改本地文件或产生可信成果物；
- 只打开了 AI 工具，但没有执行任务；
- 聊天正文中提到某个文件或 URL，但 Adapter 无法验证它是本次成果；
- 成果文件已经被删除、移出工作区或无权访问。

## 7. 使用任务灯和版本记录

### 打开与收起

- 单击浮球：展开 RunLit 任务窗口；
- 再次单击或使用界面操作：收起为浮球；
- 拖动浮球：移动到适合的位置；
- 将展开窗口拖到屏幕边缘：窗口会缩成浮球。

### 查看任务

- 单击任务灯：查看该任务的状态、版本脉络和成果物；
- 单击任务标题旁的 **打开来源** 或 **打开项目**：进入原会话入口或项目目录；
- 单击底部项目路径：打开项目目录；
- 单击眼睛按钮：隐藏或恢复任务标题与路径，适合共享屏幕时使用。

### 理解版本

RunLit 的版本不是文件每变化一次就增加一次。只有一次用户交互确实对本地文件、产品、网站或任务成果产生实质修改时，才新增一个版本。

详情默认先显示最新 3 个版本。需要完整历史时，选择 **查看更早版本**。

- 单个成果物：下方成果物按钮直接打开该文件；
- 同一次交互产生多个本地成果物：版本卡片的 **打开文件夹** 打开它们的共同目录；
- 可信网页成果：直接打开对应链接；
- 无法验证的路径或链接：不会伪装成已确认成果。

### 从灯条删除任务

1. 右键单击任务灯；
2. 选择 **删除任务**。

该操作只是从灯条隐藏任务，不会删除 AI 会话、版本记录或本地成果文件。同一个 Provider 会话以后再次产生运行事件时，RunLit 会恢复任务，并保留原有版本脉络。

## 8. 刷新、退出与自动同步

RunLit 正常情况下会自动检测新任务和状态变化，不需要手动刷新。当前内置 Adapter 默认约每 5 秒扫描一次。

顶部状态会区分 RunLit 后台连接与 AI 工具健康度。例如“2/2 工具正常”表示两个已启用工具都在最近 20 秒内成功检测；黄色状态表示至少一个工具连接异常或检测已过期。

如果接入状态刚刚发生变化，可以：

- 在 **AI 工具接入…** 页面选择 **重新检测**；
- 右键浮球或通知区域图标，选择 **刷新**，重新加载界面。

要完全退出 RunLit，请右键浮球或通知区域图标并选择 **退出 RunLit**。关闭或隐藏窗口不一定会停止后台；使用退出命令会同时停止桌面程序和本地 daemon。

## 9. 本地数据与隐私

RunLit 当前设计为本地优先。Adapter 只应保留完成任务观察所需的信息：

- Provider 与会话标识；
- 任务标题；
- 工作目录；
- 开始、活动、完成或中断状态；
- 成果物文件路径或可信 URL；
- 时间与证据强度。

RunLit 不应保存聊天正文，也不应读取浏览器 Cookie、密码或私人登录令牌。

Windows 安装版默认把数据库、设置、本地 API 授权令牌和日志保存在：

```text
%LOCALAPPDATA%\com.runlit.desktop
```

开发模式默认使用仓库中的 `.runlit` 目录。删除任务灯不会删除这些数据，也不会删除 Codex、WorkBuddy 或项目中的原始数据。

`auth-token` 只供 RunLit 和本机 Adapter 访问 localhost 服务使用。不要把它粘贴到聊天、日志或 GitHub Issue，也不要提交到仓库。

如需完全清除 RunLit 本地记录：

1. 完全退出 RunLit；
2. 如有需要，先备份上述目录；
3. 删除 `%LOCALAPPDATA%\com.runlit.desktop`。

卸载应用可能不会自动删除用户数据库和日志，因此需要完全移除时请同时检查该目录。

## 10. 故障排查

### 一直显示“等待连接”

- 从通知区域选择 **退出 RunLit**，然后重新启动；
- 检查是否有另一个程序占用了本地端口 `47831`；
- 查看 `%LOCALAPPDATA%\com.runlit.desktop\logs` 中的启动和 daemon 日志。

### Codex 显示“未发现”

- 确认 Codex 能独立运行；
- 重新启动 Codex 和 RunLit；
- 在 **AI 工具接入…** 中选择 **重新检测**；
- 从源码运行时，可将 `RUNLIT_CODEX_PATH` 设置为实际 Codex 可执行文件。

不要把某个用户的固定用户名、盘符或 Codex 版本哈希写入 RunLit 源码。

### WorkBuddy 显示“未发现”

- 确认 WorkBuddy 至少运行过一次；
- 确认选择的是 `.workbuddy-ai` 根目录，并且其中存在 `projects`；
- 在 **AI 工具接入…** 中保存路径并重新检测。

### Adapter 已连接，但任务没有出现

- 确认本次交互真的产生了本地修改或成果物；
- 等待最多 20 秒；
- 确认成果仍在当前工作区中且可以访问；
- 查看 Adapter 卡片是否出现最新错误；
- 只聊天、不修改成果的会话被排除属于正常行为。

### 任务一直显示进行中

- 等待最多 20 秒，让 Adapter 读取结束事件；
- 检查对应 Adapter 是否仍为 **已连接**；
- 选择 **重新检测**；
- 如果 AI 工具异常退出，RunLit 可能显示“已中断”或“状态未知”，而不是伪造“已完成”。

### 成果物无法打开

- 检查文件是否被移动或删除；
- 检查当前 Windows 用户是否有访问权限；
- 使用版本卡片的 **打开文件夹** 定位本次多个成果物的共同目录。

## 11. 已知限制

- 当前公开目标仅为 Windows x64；
- 当前内置 Adapter 仅包括 Codex 和 WorkBuddy AI；
- 默认只回看最近 24 小时的 Provider 会话；
- Provider 的本地数据格式升级后，Adapter 可能需要同步更新；
- RunLit 不从普通聊天文本推断远程成果 URL；
- 当前没有云同步，也不会把一台电脑上的任务自动同步到另一台电脑；
- 自动更新机制完成前，新版本需要从 GitHub Releases 手动下载安装；
- 未签名开发版可能触发 Windows 安全提示。

## 12. 从源码运行

面向开发者的源码运行环境：Node.js 24+、npm、Rust MSVC 工具链和 WebView2。

```powershell
npm ci
npm run start:runlit
```

创建指向当前仓库的桌面快捷方式：

```powershell
npm run shortcut:install
```

这类快捷方式指向本机仓库，不等于正式安装包。普通用户应优先使用 GitHub Release 中的安装程序。

## 13. 反馈问题与安全问题

公开发布后，一般功能问题请通过 GitHub Issues 反馈，并提供：

- RunLit 版本；
- Windows 版本；
- AI 工具及其版本；
- **AI 工具接入…** 页面中的状态；
- 问题发生时间和可复现步骤；
- 已删除用户名、工作路径、会话 ID、令牌和聊天内容的日志片段。

安全漏洞不要直接公开包含敏感信息的 Issue。请使用仓库 `SECURITY.md` 指定的渠道或 GitHub 私密漏洞报告功能。
